# T40 雷达 0x00F0 逆向：结论与方法

这个 skill 有两部分：**能直接拿去用的结论**（第一节，不需要再逆向），
和**怎么得出这些结论的过程**（第二、三节，换一颗雷达/换一版固件时照着重跑）。

配套的四份带数据报告在 `references/`，本文件是它们的压缩版 + 可复现步骤。

---

## 一、结论速查（可以直接拿去写解码器）

### 1.1 链路前提：不打通这个，雷达一个点都不给

雷达不是"上电就吐点云"。要让它出 0x00F0 / 1E61，必须同时满足：

1. **雷达连上 SSID 为 `radar_wifi` 的开放热点**（5G ch48，802.11a legacy 20 MHz，无 HT）。
   雷达是 STA 且**被动扫描**：只听 beacon、不发 probe request，所以 AP 必须是它自己那颗
   AR1021x；用别的网卡起同名热点它不认。
2. **主机以 10 Hz 往 `192.168.8.2:50007` 发 `0x1E21 flight_pos`（mode=2）** —— 控制面心跳，
   不开这个 1E61 永远是 69 字节空包。
3. **雷达与 ESC 之间的电机 DUML 必须双向桥接**（雷达 50007 ↔ CAN 0x0A2/0x0A3）。
   不桥接，雷达的 motor FSM 停在初始态，同样不出点。

第 2、3 条是"空包"问题的根因，实现见仓库的 `host/radar_min.py`。

### 1.2 0x00F0 容器（3665/3665 帧验证通过）

```
DUML v2 帧头（27 B，magic 03 10 07）之后是 0x00F0 的 payload：

偏移  长度  内容
0     1     0x00
1     1     0xF0 / 子类型
2     1     ...
3     2     流水号 u16 LE
...
13    2     记录区字节数 N_bytes u16 LE   ← 唯一的长度真值
15    1     批数（常态 01）
16    1     批索引（常态 01）
17    1     sum8(记录区) & 0xFF           ← 校验和 1
18    1     sum8(body[1:18]) & 0xFF       ← 校验和 2
19    N     记录区 N_bytes = N×12
```

判定一帧合法的四条硬约束（全部要满足，否则丢弃）：

```
nbytes = u16@13
nbytes != 0  and  nbytes % 12 == 0  and  19 + nbytes <= len(body)
body[17] == (sum(raw) & 0xFF)
body[18] == (sum(body[1:18]) & 0xFF)
```

**它不分片**：一个 UDP 包 = 一整帧，没有尾部 CRC32，没有续帧。曾经按"分片"假设做的
两版解析器全部作废——先做长度自洽性检验就能一步否掉。

### 1.3 0x00F0 记录（12 B = 6×u16 LE）

| 字段 | 含义 | 单位 | 量化 / 备注 |
|---|---|---|---|
| c0 | 方位角 | mrad | **268 格/圈**，步长 23.4438 mrad，残差 p50 0.27 mrad |
| c1 | 俯仰角 | mrad | 存 `(el + 2π)`，减 6283 得实际值；**sin(el)=k/64**（64 元 DBF），覆盖 −59°…+53° |
| c2 | 距离 | mm | u16 回绕 65.5 m；**一格 39.70 mm** ⇒ 带宽 3.78 GHz；最小 1.27 m |
| c3 | 幅度类 | 0.01 | 近场饱和、远场滚降；物理名未定 |
| c4 | 幅度类 | 0.01 | 与 c3 同形；物理名未定（**不要**断言是 SNR） |
| c5 | 探测时刻 | µs | 绕内偏移，帧内单调；对 c0 的斜率 = 转速 |

一帧 = 一圈；固定约 179 格 ≈ 239.1° 有数据，**121° 空档对称于 az=0**（正前方），
最强回波集中在扫描首末格（起停瞬态），不是地面。

固件来源（写入函数 `0x4CBF8`，逐寄存器追出，带整数截断）：

```
tv = table[base + i]                    // 常态 base=0，table[i]=i
c0 = (u16)(A[tv].x * 1000)              // s10 = 1000.0
c1 = (u16)((A[tv].y + 2π) * 1000)       // s8  = 6.28319
c2 = (u16)(A[tv].z * 1000)
c3 = (u16)(B[tv].x / 100)               // s9  = 100.0
c4 = (u16)(B[tv].y / 100)
c5 = (u16)(C[tv] - count)
```

数组布局（都在雷达进程的数据段，间距 `0x1D4C0` = 10000×12）：

| 东西 | 地址 | 规模 |
|---|---|---|
| 索引表 | `0x0C451A30` | 10000 × u16 |
| 源数组 A（角度/角度/距离） | `0x0C456850` | 10000 × 3×float |
| 源数组 B（幅度类） | `0x0C473D10` | 10000 × 3×float，用前 2 |
| 源数组 C（µs 时间戳） | `0x0C4911D0` | 10000 × 4 B |
| body 缓冲 | `0x0C442F90 + 0x28` | 19 B 头 + N×12 |
| 计数 | `0x0C451A2C` | u16，c5 的基准 |

> 地址是**这一版 app.elf** 的，换固件必须重定位（见 3.6）。

### 1.4 两条必须记住的几何修正

- **0x1E61 与 0x00F0 的原始方位差 180°**（x、y 同时反号）。两路点云要叠加，先给 c0 加 π。
  这是用最近邻在 0.14 m 内对上扫出来的，不是猜的。
- **c0=0 不是画面正上方**：仓库上位机默认把整幅画面逆时针转 180°，就是为了让 0°（正前方）
  落在画面下方；改朝向必须重投影历史点（旧点已算成像素坐标）。

### 1.5 转速：别信设定值，用 c5 反推

同一帧内 c5 对 c0 的斜率直接给转速（µs 与 mrad 都是固件原生量，不需要标定）：

```
rpm = 60e6 / (slope[µs per mrad] * 6283.19)
```

实测三种独立估计（帧率、帧头两条 µs 计数器的 ∆t、c5 斜率）互差 < 1%：
设定 1200 → 实测 1235.6 / 1228 rpm。**设定值 1200 实测只有 905 rpm 的情况也遇到过**，
所以任何跟转速有关的实验都先读 CAN 上的 `0x1E0F` 或反推 c5。

## 二、方法论：把"猜"变成"定论"的九个步骤

这套流程适用于任何**私有二进制协议**（自研雷达、IMU、图传），不只这颗雷达。
核心思想：**每一步只允许一种解释活下来**，最后用两条互不依赖的通路对撞。

### 步骤 0 · 准备：先建立可控的观测面

- 拿到固件（`/home/root/app.elf`，ARM 32 位、静态链接、glibc 2.18）。
- 确认业务进程，并且能**反复重启它**（`radar.autorun` 会把它拉起来，调试前先 kill 掉）。
- 确认抓包点：在雷达 AP 网卡上 `tcpdump -i <iface> -s0 -w x.pcap udp port 40204`。
- 记录一切"能对照的真值"：ESC 上报的转速（CAN `0x1E0F`）、雷达自带 xyz 的另一路报文
  （`0x1E61`）、场景的实际几何（墙在哪、几米）。**这些是后面唯一的裁判。**

### 步骤 1 · 被动抓包，但落盘要留原始字节

抓包工具只做一件事：给每个 UDP 包打上**板卡单调时钟**时间戳，整包 hex 落 JSONL。
不要在这一步做任何解析——解析假设一旦错了，原始字节还在就能重解。踩过的坑：
只存解析结果的抓包，在改了两版假设之后全部作废，白抓。

### 步骤 2 · 先看时序，别急着看字段

对每个 msg_id 统计到达间隔、与转速的关系、seq 是否连续、和别的 msg 是否成组。
这一步产出的结论往往比字段本身更硬：

- 0x00F0 每转一圈一帧（帧率 ≈ rpm/60），**锁相**：转速扫描时帧率线性跟随。
- 节拍是「3 短 1 长」：每圈 2 帧 1E61 + 1 帧 0x00F0。
- 头里两条 µs 计数器增量 p50 = 48.86 / 48.92 ms，恒定相差 2.928 s —— 同一时刻在两个
  流水线上打点，或两个时钟域。

有了"一帧 = 一圈"，后面所有几何量都能用"一圈 360°"去校核。

### 步骤 3 · 容器层：用长度自洽性暴力扫描

**不要**先猜字段语义。先确定"记录从哪开始、一条多长、有几条"。
做法：对每个候选 (header_len, rec_len)，检查全体样本的
`payload_len == header_len + N*rec_len` 是否同时成立，并检查候选长度字段是否恒等于
`payload_len - header_len`。

一颗 12 字节的记录、19 字节的头，就是在 (1..64) × (1..64) 的枚举里唯一能让
3665 帧全部整除的组合。判据是**全体样本**，不是几帧。

### 步骤 4 · 字段层：先做"否定"，别做"命名"

对每列做统计分析，**先把不可能的排除掉**：

- 单位：帧内单调 + 跨度恰好覆盖一圈 ⇒ 方位角（c0）；对 c0 严格线性（corr=1.00）⇒ 时间量（c5）。
- 量化：算相邻取值的最小公差。c0 步长 23.4438 mrad ⇒ 一圈恰 268.0 格；
  c2 步长 39.70 mm ⇒ 带宽 3.78 GHz（与 3.78 GHz 的调频带宽吻合，这条比"分布像距离"硬得多）；
  c1 的 107 个离散值全部落在 `asin(k/64)` 上 ⇒ 64 元虚拟阵 DBF 波束格。
- 单调性/回绕：u16 在 65.5 m 回绕 ⇒ 毫米量纲。

反面教材（都真踩过）：

- "全体记录的距离分布与另一路点云吻合" —— **不是证据**，噪声地板占主导，谁比谁都能吻合。
- "近场尖峰 = 地面回波" —— 实际只出现在扫描首末格，是起停瞬态。
- "c4/c3 随距离 0.85→0.3 = SNR" —— 换场景后实测 0.08→0.47，方向都反了。
  两个字段的物理名就停在"幅度类"，别硬起名字。

### 步骤 5 · 静态：从"谁在发"倒着找"谁在写"

按这个顺序找，成功率最高：

1. **常量搜**：在 `.text` 里搜立即数 `0xF0` 及其周围（`0x0032`、`0x1E61` 一起搜），
   找出消息描述符构造点（0x00F0 这条在 `0x307DC`，构造一个 0x2c 字节的描述符）。
2. **路由表**：描述符按 `(byte0, byte1)` 查一张 `0x2c` 步长的路由表（这里在 `0x11FF60`），
   `b` 尾跳转一路到通用打包发送函数（`0x13298`）。
3. **向上找调用者**：`0x13298` 的四个调用者传的 payload 都只有 0x28/0x34 字节，
   对不上 0x00F0 的 451–1099 字节 ⇒ 真正的 payload 是**按指针**传的，还得再往上一层。
4. **找到全局缓冲区**：真正的发起者 `0x4CE58` 里 `ldr r2,[pc,#..]` 拿到 `0x0C442FB8`，
   把这块全局缓冲当 payload 交出去。到这里，**内存地址和线上字节就能逐字节对上了**。

判据：内存 dump 出来的 body 必须和线上抓的包**逐字节相等**。这一条过了，
地址就不会错，后面 `/proc/pid/mem` 才有意义。

### 步骤 6 · 动态：LD_PRELOAD 拦 sendto 抓整段栈

静态到了"payload 是全局指针"这一步就够了；想知道**记录是谁写进缓冲的**，
必须在发送那一刻看调用栈。可复用做法（下面这段 shim 是核心，自己照着写一个就行，
原始版本叫 `bbxspy.c` / `bbxspy2.c`，没随仓库发布）：

```c
/* 要点 1：-nostdlib 裸 syscall。雷达 glibc 2.18，新工具链链出的 .so 带
 *         GLIBC_2.3x 版本符号，ld.so 直接拒绝加载。只用到 open/write/close。 */
/* 要点 2：窗口不能写死。发送函数的栈帧有 64 KB（sub sp,#0xFF00; sub sp,#0xD4，
 *         而且 push {r4-r9,lr} 没有 r11 ⇒ 没有帧指针链可走），48 字的窗口
 *         够不到调用者的返回地址。 */
/* 要点 3：上界必须从 /proc/self/maps 里取包含当前 fp 的那个 mapping 的 end，
 *         盲扫 96 KB 会越过栈顶踩到未映射页，把雷达 app 打死。 */

ssize_t sendto(int fd, const void *buf, size_t len, int flags,
               const struct sockaddr *addr, socklen_t alen)
{
    unsigned *fp = __builtin_frame_address(0);
    unsigned  top = map_end_for((unsigned)fp);      /* 读 /proc/self/maps */
    dump_words(fp, top);                            /* write 到 /tmp/bbxstack.bin */
    return sys_sendto(fd, buf, len, flags, addr, alen);   /* __NR_sendto = 369 (ARM) */
}
```

编译（Vitis 自带的 `arm-none-eabi-gcc`）：

```bash
arm-none-eabi-gcc -O2 -fPIC -shared -nostdlib -mcpu=cortex-a9 -marm \
                  -fno-omit-frame-pointer -o bbxspy.so bbxspy.c
```

部署与恢复：

```bash
kill $(pgrep -f radar.autorun)          # 不然它会把 app 拉起来
kill $(pgrep -f app.elf)
LD_PRELOAD=/tmp/bbxspy.so nohup /home/root/app.elf &
# 约 40 秒后才开始出 0x00F0
# 恢复：kill 掉，然后 nohup /home/root/radar.autorun &
```

离线筛真返回地址：栈上大量数据会碰巧落在 `.text` 范围里，**只有"这个地址前面那条指令
是 BL/BLX"的才是真返回地址**。落盘格式（小端 u32）：
`magic(0x42425358) ra len buf fd fp sp top nwords nchain` + 帧链 + 原始栈字。

这一步的产出是调用链（全是 `b` 尾跳转，所以 LR 一路不变）：

```
0x307DC (构造描述符) └ bl 0x14914 → b 0x1488C（路由表）→ b 0x135A8 → b 0x133C0
                    → b 0x13298（打包发送）→ 0x16464 → 0x16268 → 0x11C8C → 0xF4D0 → sendto@0xF528
```

### 步骤 7 · 内存快照：把公式逐条复算

拿到全局缓冲区地址后，直接读进程内存做**离线复算**，比反复插桩快得多：

```bash
# busybox dd 读不了 >2GB 的偏移（off_t 是 32 位），自己写个用 _llseek / pread64 的小工具
./memrd <pid> 0x0C442F90 0x200        # 19 B 头 + 首批记录
./memrd <pid> 0x0C456850 0x1D4C0      # 源数组 A 整块
```

然后用固件里的公式把 A/B/C 复算成记录，和线上包逐条比。
**两条通路（网络 / 内存）解出来的距离分布相关系数 0.984** —— 这条一致性同时排除了
"地址读错"和"公式套错"两种可能。

⚠ 快照是"边写边 dump"的，多数组之间会错位（本案例 B 从 80 号开始、C 只有尾部有值）。
想要干净的三联，得在**发帧那一刻**同时停住，或者改成发帧后立刻读。

### 步骤 8 · 交叉验证：三条独立证据才叫定论

本案例里每个字段至少三条互不依赖的证据：

| 字段 | 证据 |
|---|---|
| c0 方位 | 帧内随 c5 严格线性（corr=1.00）／268 格一圈／239° 扇区对称于 az=0 |
| c1 俯仰 | 107 个离散值全落 `asin(k/64)`／残差 ≤1.1 mrad／与 1E61 xyz 对齐 |
| c2 距离 | 39.7 mm 格 ⇒ 3.78 GHz 带宽／最小 1.27 m ↔ 规格 1.5 m／3.6 m 空腔的多次反射阶梯 |
| c5 时间 | 斜率 → 1235.6 rpm／帧头 ∆t → 1228 rpm／设定 1200 |
| 整体 | 0x00F0 反算 xyz 与 1E61 自带 xyz 最近邻 **0.14 m** |

最后一条（用另一路**已知**点云当标尺）是最强的：它不是"看起来像"，而是同一个物理点在
两套报文里落在同一个位置。做这类逆向时，**先找有没有第二路已知格式的数据**——
有的话，所有字段的最终裁决都交给它。

## 三、坑清单（省掉重复踩）

1. **别信"分片"**：0x00F0 不分片。先做长度自洽性检验，能一步否掉的假设不要花两天。
2. **`LD_PRELOAD` 的 .so 必须 `-nostdlib`**：目标 glibc 2.18，带 GLIBC_2.3x 符号的 .so
   会被 ld.so 直接拒绝（报错还很不直观）。
3. **栈窗口不能写死**：目标函数 64 KB 栈帧、无帧指针链，48 字窗口什么都看不到。
   上界必须从 `/proc/self/maps` 取，否则踩未映射页把目标打死。
4. **栈上"像代码地址"的垃圾很多**：必须用"前一条指令是 BL/BLX"过滤。
5. **`busybox dd` 读不了 >2 GB 的 `/proc/pid/mem` 偏移**（off_t 32 位），要自己写
   `_llseek`/`pread64` 的小工具。
6. **设定转速不可信**（1200 设下去实测 905）。任何转速相关实验先读 CAN `0x1E0F` 或反推 c5。
7. **雷达 USB 很挑**：`ath6kl: Failed to submit usb control message: -110` 之后
   unbind/bind、`authorized` 掉电重上都救不回来，只能**断电重上雷达**。
   正常日志是 `ath6kl: ar6004 hw 3.0 usb fw 3.5.0.349-1 api 5`；USB 接口类是 `ff`（厂商自定义），
   **没有串口可测**，判断依据只有这一行。
8. **`iw` 会永久阻塞**：ath6kl 楔死时 `iw dev ... station dump` 永不返回，
   把整个状态采集线程钉死。所有可能进 D 状态的调用都要 timeout + kill，且不能 `wait`。
9. **日期/固件版本要钉住**：本文所有地址都只对 `app.elf` 这一版有效。换固件先从
   步骤 5 的"常量搜"重新定位，别直接套地址。
10. **不要让解码假设污染抓包**：原始 hex 必须留。这行吃过一次亏。

## 四、复现清单（换一颗雷达时按这个顺序做）

```
[ ] 1. 打通链路：AP（雷达认的 SSID/信道/legacy 模式）→ 1E21 flight_pos 10 Hz → CAN 双向桥接
[ ] 2. 确认"一帧 = 一圈"：扫 300/600/900/1200/1500/1800 rpm，记帧率
[ ] 3. 抓 60 s×3 段 pcap，落 JSONL（原始 hex + 单调时钟）
[ ] 4. 容器层枚举 (header_len, rec_len)，用全体样本的自洽性定死
[ ] 5. 列统计：单调性/回绕/最小公差/离散值集合 → 单位与量化
[ ] 6. 静态：常量搜 → 路由表 → 调用者 → 全局缓冲区

[ ] 9. 交叉验证：与第二路已知格式（1E61）最近邻对齐，量出系统偏差（本案例 180°）
[ ] 10. 把"还没解决的"（盲区成因、c3/c4 物理名、42.9 m 鬼影）单独列出来，别当成已知
```
